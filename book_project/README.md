# مشروع تدريبي: تقييم الكتب

شغّل من جذر الريبو: `python -m book_project.demo`.
الناتج:

```text
Average rating: 4.0
Book not found
```

ابدأ بـ `models.py` ثم `contracts.py` ثم `repositories.py` ثم `services.py` ثم `demo.py`.
تتبع `add_review(1, 5)`: إنشاء Review والتحقق من القيم ← التأكد من وجود الكتاب ← تخزين المراجعة ← إرجاعها.
إذا فشل التحقق لا تنضاف مراجعة. أكثر من مراجعة لنفس الكتاب مسموح؛ ما في مستخدمين أو منع تكرار.
المتوسط لكتاب بدون مراجعات `None`، وليس صفر. خدمة المتوسط وحدها لا تتحقق من وجود الكتاب.

| المفهوم | مكانه وتطبيقه |
|---|---|
| Encapsulation | التخزين في حقول داخلية؛ نتيجة for_book قائمة منفصلة |
| Composition | الخدمة تحتوي مراجع لكائنات المستودعات |
| Abstraction | Protocol يعرّف ما تحتاجه الخدمة |
| SRP | Models لصحة البيانات، repositories للتخزين، services لحالات الاستخدام |
| OCP | تستطيع إضافة مستودع جديد يحقق العقود بدون تعديل الخدمة |
| LSP | البديل يجب أن يحافظ على None عند غياب الكتاب وعلى استقلال قائمة النتائج |
| ISP | فصل قراءة المراجعات عن كتابتها، وكل خدمة تطلب حاجتها فقط |
| DIP | الخدمات تعتمد على العقود، وdemo يختار التنفيذ الفعلي |

هذا مثال بالذاكرة وليس API أو قاعدة بيانات فعلية. الـ Protocol لا يفحص التنفيذ وقت التشغيل.
اختبار خدمة المراجعات مع fake مستقل يوضح إمكانية تبديل الاعتماد؛ واختبارات المستودع تتحقق من عقده.
لإضافة SQLite لاحقاً: طبّق نفس العقود، اختبر السلوك نفسه، ثم بدّل تركيب الكائنات في demo.
